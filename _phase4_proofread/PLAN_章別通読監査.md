# 章別通読監査計画

## 位置づけ

人物ペア再監査を一通り終えた後、冒頭から章・事件単位で原文と現訳を連続して読む。

人物ペア監査は、声・呼称・関係変化の局所整合に強い。一方、章通読は次を検出するための別工程とする。

- 情報提示の順序と伏線・回収
- 同一事件・人物・物品の呼び方の章内外の揺れ
- 直前の感情や判断を無視した台詞
- 選択肢、分岐、戦闘前後、移動後のつながり
- 説明の重複、脱落、主客反転、因果の断絶
- 行単位では自然でも、連続して読むと不自然な語尾・反応・テンポ
- 初見プレイヤーにはまだ分からない情報の先取り
- 既知情報を再び初耳のように扱う時系列破綻

## 実施時期

次の条件を満たしてから開始する。

1. 主要関係クラスタの人物ペア高確度パスが一巡している。
2. 主要ペルソナと関係性資料に根拠・反例・確度が記録されている。
3. 未適用の高確度修正束が残っていない。
4. 現行locresとpakが `build_verified` である。

ゲーム内確認は章通読と並行または後続でよい。章通読だけで `game_verified` にはしない。

## 監査単位

ファイルやkey番号だけで区切らず、プレイヤーが経験する物語単位で区切る。

- 序章・導入
- 主要章
- 章内の事件・任務
- 戦闘前後
- 拠点帰還後の報告
- 分岐と合流
- 仲間加入・離脱
- 告白・正体判明・継承・死亡などの転換点

一つの監査束が大きすぎる場合は、「章 / 事件 / 場面群」の三層に分ける。

## 読む順序

1. 原文を章順に読む。
2. 現訳を同じ順で読む。
3. 原文と現訳を場面単位で突き合わせる。
4. 人物ペア監査で確定した規則と衝突する箇所を確認する。
5. 衝突時は一次資料を優先し、人物資料側の誤りも疑う。

訳文だけを日本語小説として読むパスと、原文対照パスを分ける。最初から一行ずつ対照すると、章全体の読後感や情報順序を見失いやすい。

## 一章ごとの成果物

- 章・事件の範囲とkey座標
- 登場人物と関係段階
- 章開始時にプレイヤーが知っている情報
- 章終了時に新たに判明した情報
- 重要語・事件名・物品名
- `fix / keep / source-doc-fix / unresolved`
- 高確度修正JSON
- 意図的保持一覧
- 次章へ持ち越す未解決事項
- 適用・ビルド検証記録

## 判定軸

### 意味

- 誰が誰に何をしたか
- 否定、推量、疑問、命令、許可の方向
- 因果、条件、時系列
- 固有名詞、技、門派、事件、物品
- 情報の追加・脱落・先取り

### 声

- 同じ場面内の感情の連続
- 反応の強さと間
- 直前発話への受け答え
- 短句、言いさし、沈黙、効果音
- 場面の緊張とテンポ

### 関係

- 呼称と二人称
- 敬体・常体
- 公私、敵味方、上下関係
- 関係成立・悪化・和解の前後
- 知っている事実の差

### 物語

- 伏線と回収
- 初見情報と既知情報
- 章内の目的と結果
- 分岐間の整合
- 次章への接続

## 修正の優先順位

1. 意味反転、主客反転、情報の追加・脱落
2. 時系列・知識状態・伏線の破綻
3. 人物関係・呼称・registerの誤り
4. 場面感情と会話接続の破綻
5. 直訳臭・時代錯誤・不自然な日本語
6. 好みだけの言い換えは行わない

## 完了状態

- `chapter_inventory`: 章範囲、場面順、主要人物、情報状態を棚卸し済み
- `chapter_reaudited`: 章全体を日本語通読と原文対照の両方で監査済み
- `chapter_build_verified`: 章修正をlocresへ反映し、pakと回帰検証を完了
- `chapter_game_verified`: ゲーム内で章の重要場面を確認済み

全章の `chapter_reaudited` が完了しても、表示・分岐・実際の演出確認をしていない限り `game_verified` とはしない。
