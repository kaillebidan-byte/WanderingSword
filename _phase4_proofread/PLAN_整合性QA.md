# PLAN_整合性QA — 人物・関係性・既訳の品質再監査

## 背景

888キャラのキャラ単位校正は一巡した。しかし、この「完了」はカーソルを最後まで進めたという意味であり、最終品質保証ではない。

横断作業で次が確認された。

- ペルソナの規則自体に、相手カテゴリや時系列の混同がある。
- 関係性・呼称マップは呼称マーカー集計が中心で、発話相手、場面、関係変化を十分に表していない。
- 完了済みの既訳にも、意味の過不足、声の平板化、呼称の向き違い、過剰敬体が残る。
- 単語一致lintは誤検出が多く、人物資料を正本として機械適用すると正しい揺れまで壊す。

したがって、従来の「ペルソナとマップを基準に既訳を直す」方式から、**原文・現訳・前後文を一次資料として、ペルソナ・マップ・既訳を同時に再検証する方式**へ移る。

## 資料の優先順位

1. 原文zh・現訳ja・会話前後・ゲーム内場面
2. 同一人物・同一関係の別出現と時系列
3. 用語・設定の正本
4. ペルソナと関係性・呼称マップ
5. 過去の校正ログ・完了記録

ペルソナとマップは作業仮説。一次資料に反例があれば資料側を改訂する。

## 進捗段階

`_phase4_proofread/audit_status.json` で次を別管理する。

1. `initial_pass`: 初回キャラ校正を一巡
2. `evidence_inventory`: 原文・現訳・前後文・呼称・時系列を抽出
3. `persona_reviewed`: ペルソナの規則を根拠と反例つきで再検証
4. `relation_reviewed`: 関係性と呼称の時系列・場面差を再検証
5. `translation_reaudited`: 対象既訳を意味・声・関係性の三面で再読
6. `game_verified`: 反映後にゲーム内確認

`status: 確定` や `char_progress` 完走だけでは、3以降を満たしたことにならない。

## 作業単位

キャラ単独ではなく、次の順で処理する。

1. **関係クラスタ**を決める
2. クラスタ内の**人物ペア**を1組選ぶ
3. 両者が同席する会話ブロックと相互呼称行を抽出
4. ペルソナと関係性マップの主張を一次資料で検証
5. 既訳を意味・声・関係性の三面で再監査
6. 修正案、資料改訂、未確定事項を分離して記録
7. 検証済み修正だけをJSON化する

相手不明の行は推測で統一せず、未確定キューへ置く。

## 監査順

### 1. 武当師門中核

主人公の基調、師弟関係、主要呼称、敬体と常体の境界を先に確定する。

1. 宇文逸↔清虚道長
2. 宇文逸↔清霄道長
3. 宇文逸↔莫問
4. 宇文逸↔莫棄
5. 宇文逸↔元啓
6. 宇文逸↔元風
7. 宇文逸↔程鈺

### 2. 宇文逸の近親・義兄弟・親密関係

白錦、李元興、江小彤、欧陽雪、呂仙児、司馬鈴など。

### 3. 多モード主要人物

顧思帰、莫問、絶無心、冷鷹など、相手や場面で声が大きく切り替わる人物。

### 4. 門派横断・役職・呼称

師兄弟の向き、掌門・方丈・教主・神侯等の役職、派閥間の敬度を点検する。

### 5. 残り人物と端役

主要関係で確定した規則を利用しつつ、個別反例を拾う。

## 抽出と検出

- `_tools/extract_relation_context.py`: 人物ペアの同席会話と相互呼称を原文・現訳・前後文つきで抽出。
- `_tools/lint_register.py`: 一人称・二人称・register候補を機械抽出。
- 機械検出は候補作りだけ。採否は一次資料で個別裁定する。
- 直接会話、第三者への言及、回想、選択肢分岐を混同しない。

## 適用

- 修正案は複合キー単位のJSONにする。
- 適用前に key存在、新旧差分、話者接頭辞、タグ、改行、プレースホルダを検証する。
- locres/pak反映とゲームへのデプロイは分ける。
- 反映後も `game_verified` までは完了扱いにしない。

## 最初の対象

現在は **宇文逸↔清虚道長** の `evidence_inventory`。

確認事項:

- 宇文逸の「師父／掌門／清虚道長」の時系列と場面差
- 清虚の「逸児／小逸／徒児」の条件
- 師弟間の敬体・常体・感情表出
- 宇文逸・清虚両ペルソナの反例と不足
- 関係性・呼称マップの不足
- 既訳の意味ズレ、平板化、呼称誤り
