# SPEC — 手動校正Webツール（人間の最終確認パス）

> フェーズ2校正の**人間による最終確認**を支援するローカルWebツールの仕様。
> 既存LLM校正パイプライン（pending/apply_proofread, loop_proofread）の**後段**に位置し、置換しない。
> 反映（locres書き戻し→repak→deploy）は既存CLIゲートを通す。本ツールは**オーバーレイJSONを書くだけ**。

## 1. 目的と位置づけ
- LLM校正後の行を人が最終チェック・微修正する。CLAUDE.mdの芯＝**声の非平坦化**を、場面なりきりと文脈理解で確認する。
- 既存の `cursor.json`（LLMループ用）とは**別の進行ログ**を持ち、衝突しない。

## 2. 形態
- **ローカルWeb**：Python標準ライブラリ `http.server`（`_tools/手動校正/proofread_server.py`）＋単一HTML/JS。外部依存なし。
- 起動時にlocres全targetを `locres.parse` でメモリ展開。`PYTHONIOENCODING=utf-8` 前提。
- **配置**: ツール一式は `_tools/手動校正/`（server / ui / apply_manual / proofread_start.ps1 / proofread_deploy.ps1 / SPEC / 手順書）。共有モジュール(`locres.py` `locres_write.py`)は `_tools/` のまま参照。

## 3. データ配線（すべて既存資産で足りる）
| パネル | 出所 |
|---|---|
| 行の並び（会話順） | `_phase4_proofread/queue.json`（DlgId/Index順＝実会話） |
| 原文ZH | `_phase4_proofread/source_zh.json` |
| 現訳JA | locres（`_work/jp/.../zh-Hans/*.locres`、起動時展開） |
| 話者名・キャラ束 | `by_character.json` を**逆引き**（フルキー→JP名）。簡体→JP辞書は不要 |
| ペルソナ | `10_人物/<JP名>.md` の `声の核`＋`完成例`＋`status:` |
| フォールバック（モブ/非対話） | `00_ルール/`（基本翻訳・口調指針・glossary） |

## 4. タブ構成
```
[対話]   100行未満 / 100–400 / 400以上     ← ペルソナ軸・会話順
[非対話] 用語(Buff/Skills/Npc) / クエスト / UI(系统) / その他   ← glossary軸
[全行]   会話順スキャン（OptionTextを選択肢として挟む）
```

### 4.1 対話タブ（行数バケット）— by_character.json の count から算出
| タブ | キャラ数 | 行数 |
|---|---|---|
| 100行未満 | 806 | 11,251 |
| 100–400 | 60 | 11,334 |
| 400以上 | 22 | 30,806 |

- 各タブ内のキャラは**行数降順**。レビュー状態が入ったら `承認 X/Y` を併記。
- **100行未満タブのみ**：806キャラと多いので **キャラ名検索ボックス**を付ける（うち1行のみ205、2–9行298の極端なテール）。
- キャラを開く → そのキャラの行を**会話順**で表示。前後文脈は他話者も含めて見せる。

### 4.2 非対話タブ（target別サブタブ）— 計19,561件
| サブタブ | 件数 | 中身 | 校正軸 |
|---|---|---|---|
| 用語 | 5,357+1,506+2,743 | Buff/Skills/Npc の Name・Description・PictorialName 等 | glossary一貫性 |
| クエスト | 4,981 | クエスト名・目標（OptionText除く） | 用語・簡潔さ |
| UI(系统) | 3,816 | UIラベル（hexキー含む） | **文字数制限・簡潔さ・改名** |
| その他 | 617+531+10 | 程序_导出・门派地图与提示・坐骑 | 用語 |

- 右袖はペルソナでなく **glossary/関連語**を出す。
- UI(系统)は長さ制約あり（hexキーUI作業と地続き、メモリ参照）。

### 4.3 全行タブ（会話順スキャン）
- queueを純粋に会話順で流す。
- **OptionText（選択肢）を会話に挟む**：`<ID>_OptionText<n>` を同じ先頭IDの対話ブロックに `▶選択肢` として挿入。
  - 紐づけ：701/705のIDがDlg IDと一致。オーファン（約4件）は末尾フォールバック表示。
  - ブロック内順序：sub-block（Request→Finishing）→Index、OptionTextは選択肢群として付随。

## 5. 編集ユニット（1行）
- 中央：現訳JA。**`$@$`より前（ID・話者名）は編集不可ロック**、本文のみ `textarea`。
- 上：原文ZH＋話者名（JP）。
- 左右：前後の会話（queueの±N行）。話者交代も続けて表示。
- 右袖：ペルソナ（`status:`バッジ付き）／無ければ共通ルール。

## 6. 保存（オーバーレイ）
- 置き場：`_phase4_proofread/manual_edits.json`
  - 形式：`{ "<target>\x1f<ns>\x1f<key>": {"new_ja":..., "state":..., "note":..., "ts":...} }`
- locres直書きはしない。反映は既存 `apply_proofread`→repak→deploy。
- **保存時バリデーション（1つでも崩れたらブロック）**：
  - `$@$` 接頭辞の不変
  - `<Y></>` 等の色タグ対応
  - `#nl` / `\r\n`（改行）の消失なし
  - `{0}` 等プレースホルダの消失なし

## 7. レビュー状態モデル
- 進行ログ：`_phase4_proofread/manual_review.json`（cursorと別）。
- 状態：`未` / `OK(現訳のまま承認)` / `修正` / `要再訳(LLMへ差戻し)` / `skip`。
- `要再訳` は既存LLMループへ戻す導線になる。

## 8. ペルソナ関門の可視化（CLAUDE.md準拠）
- `status:` が `確定` 以外（仮訳/なし/保留）の行は**赤帯で警告**。編集は許すが注意喚起。
- `保留`（宇文逸/主人公）は声・呼称に手を入れない方針を明示表示。

## 9. 非スコープ／既存に委ねる
- ゲーム反映（repak/deploy）— 既存CLI。
- LLM校正の実行 — 既存 loop_proofread。
- glossary編集 — 別途。

## 10. 実装メモ（規模感）
- フルlocres 73,189キー＝対話 約53,628 ＋ 非対話 19,561。CG表(38,711)は全対話＝本編。
- 起動時メモリ展開で全件保持可能（数十MB）。検索・フィルタはクライアント側JSで十分。
