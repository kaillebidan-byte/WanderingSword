### draft v2.1

Wandering Sword日本語翻訳MODの校正(フェーズ2)を1回分実行する。

作業フォルダ: Claude Code を起動したプロジェクト直下(= `Wandering Sword翻訳`)。
実行環境はWindowsネイティブ。冒頭で次を設定する(bash):
`export WS_TMP="$PWD/_ws_tmp"` … 中間ファイル置き場。
`export PYTHONIOENCODING=utf-8` … **必須**。無いと `pending_char.py` 等の stdout/print が cp932 でcrash(exit 1)し、deployログも文字化けする。
`python` は 3.12(`python3` も可)。

## ★最優先(これがこの仕事の目的)
**キャラの声を平坦にしないこと＝場面なりきりと文脈理解**。「このキャラがこの場面でどう喋るか」を再現する。
- **一人称修正と誤訳検出は前提条件であって目的ではない**。この2つ"だけ"に痩せるのは失敗(チェックは通るのにキャラが死ぬ)。
- 多モードキャラ(例 顧思帰=風雅↔殺意、莫問=3モード)は、**モードの落差・比喩・相槌・詩情を平板に均さない**。
- 各バッチで対象キャラの `10_人物/<キャラ>.md` の `声の核`＋`完成例` を**先に読み**、平坦化した行を声に引き戻してから、一人称・誤訳を整える。

## ★MTの癖(平坦化)を狩る — 一覧は指針が正本
MTが声を壊す典型パターン(声の平坦化・半端漢字残り・一人称固定・呼称ズレ・笑い/咳の混同・暴力の希釈 等)の
**一覧と定訳は `00_ルール/世界観口調指針.md` の「§よくあるMT誤訳と定訳」が正本**。校正前に必ず読む。
- これらは**全キャラ共通の「症状の型」**。**直す先の正解(語尾・一人称・呼称)は必ず今回のキャラの `10_人物/<キャラ>.md` から取る**。
  指針の例を全キャラに当てない(少女・老人・武人・雅士で正解は全く違う)。
- 「直すのは根拠のない揺れだけ」。原文や関係性に根拠のある使い分けは**保持**する。

## ★読むもの(最小限＝コスト削減の最大の効き目)
確定ペルソナの**継続校正は足場が効く**ので、毎回フル資料を読み直さない(これが1回20k浪費の主因)。
- **毎回必須(これだけ)**: 今回キャラ `10_人物/<キャラ>.md`(声) / `00_ルール/世界観口調指針.md`(§MT癖) / `00_ルール/関係性・呼称マップ.md`(他者・宇文逸への呼称。相手が出る場合)。
- **必要時だけ都度参照**: `人称対応表.md`(一人称に迷う時) / `典故・古典引用ノート.md`(古典引用が出た時)。
- **読まない**: `語調技法カタログ_LoM参考.md`(ペルソナ確定=Opus用。継続校正には不要) / **RUNBOOK全文**(手順は下記に要約済。詳細が要る箇所だけ拾い読み)。

## 手順
1. **RUNBOOKは全文通読しない**(手順は本指示文に要約済み。1回の作業量・完走条件・数珠つなぎ等の詳細が要る時だけ `_tools/RUNBOOK_翻訳自動実行.md` の該当箇所を拾う＝正本)。
2. `python _tools/status.py` で現在地を確認し、フェーズ2校正を実行(キャラ単位)。
   - **1依頼=1バッチ(150〜200行)を確実にやって終了**。完走していなくてよい——**続きは同じ指示文を新規セッションで再投**すれば `char_progress` が続きから再開する。
     ※RUNBOOK 5.5の「600-800行/セッション数珠つなぎ」は旧モデル。**手動Sonnetでは小さなフレッシュ session を重ねる方が安い**(実測: 200行=15k、続き131行=別session 3k。1セッション数珠つなぎは文脈肥大で割高)。
   - 完走バッチ(meta.completes_character=true)に当たった時だけ、その回で手順6の監査まで済ませる。
   - `python _tools/pending_char.py 200`(1バッチ150〜200。小さいと turn数増で割高)。stdoutは要約のみ。
   - **検出器(外部API=Gemini・コスト削減)**: `python _tools/detect_mistrans.py` を実行。各行を**2軸**で判定し `$WS_TMP/pf_char_batch.tsv` を**zhオンデマンド化**:
     **s=意味リスク**(誤訳)＋**v=演技リスク**(原文zhが皮肉・煽り・含意・古風・敬意の含みを持ち、平板訳で失われる度合い＝声に原文が要る)。**s か v が高い行だけ** `[s値/v値 理由] zh…` を残し、両方低い行は zh を空に。Google→OpenRouter自動フォールバック、落ちても安全側(全zh保持)。※検出器はペルソナ非共有(原文zhのトーンの有無だけ見る)。
     ※これで**全行がzh突合済**(意味＋演技)になる＝per-batch detectがネットの正本。完走時の全zh再突合は任意・冗長なので常用しない。
   - **`$WS_TMP/pf_char_batch.tsv` を読む**(#META / #COLS / `target⇥ns⇥key⇥zh⇥ja`。zhは s/v いずれか高い行のみ)。
   - 校正(声優先は不変):
     - **zhが空の行** = 意味も演技もOK → ja＋ペルソナで**声色のみ整える**。**文意は固定。情報の追加・脚色は禁止**(原文を見ていないので作り込まない)。
     - **zhが付いた行** = 原文を見る。マーカーで読み分け: **s高=誤訳を直す** ／ **v高=原文の含み(皮肉・煽り・古風・敬意)を声に起こす**(平板訳に埋もれた演出を出す)。
     入出力は `$WS_TMP` 配下(素の `/tmp` 不可)。
   - 修正を **`$WS_TMP/pf_inbox.json` にファイル直書き**(UTF-8。CJKをパイプ/heredocで渡さない)。形式 `{"reviewed":N,"fixes":[{"target","ns","key","new_body"}]}`。
     **`new_body` は本文($@$より後ろ)だけ**書く(話者ID・話者名の接頭辞は `apply_char` が現訳から**自動再付与**。タグ `<Y>…</>`・`\r\n`・`#nl` は本文内なのでそのまま保持)。※完全形 `new_ja` も後方互換で受理。
   - `python _tools/apply_char.py $WS_TMP/pf_inbox.json`(反映→再パック→進捗前進)。
3. 仕上げと報告もRUNBOOKの「仕上げ(毎回・両フェーズ共通)」に従う(`deploy_to_game.py`、`_handover.md`追記、`_TODO.md`へ新規横断項目のみ追加、簡潔な完了報告)。
   - **完了監査=1パスで仕留める**(★audit→fixを何周も回さない): `$env:WS_CHAR="<キャラ>"` → `python _tools/pending_char.py --audit` → **`$WS_TMP/char_audit.txt`(ja本文のみ)**。
     1) NG語を**一括Grepで全部列挙**(各キャラの `校正変換規則`＋`## 機械置換`＋`言わないこと` から)。
     2) ヒットを**2分類してから直す**:
        - **(A) 機械修正**=曖昧さゼロの1:1(半端漢字・固定呼称の表記揺れ等)。mechanical_pass で既済のはず＝残りも安全に直す。
        - **(B) 要解釈**=**呼称・一人称・口調・register**。**blind置換禁止**。場面・相手・関係を見て1件ずつ判断(根拠のある使い分けは保持)。(B)を機械的に一括置換すると声を殺す——ここだけは必ず解釈を通す。
     3) `reviewed:0` の追い直しで反映。**再audit は確認の1回だけ**。残れば残数を報告して次へ(無限ループ禁止)。

## 同一セッションでの継続フレーズ(短文・再読不要)
同じセッション内で次バッチを続ける時は、ペルソナ・手順は既に文脈にあるので**新バッチを取って読むだけ**。下記を送る:

> 続けて。`python _tools/pending_char.py 200` → `$WS_TMP/pf_char_batch.tsv` を読み、これまでと同じ声基準・同じ手順で次バッチを校正(修正は `new_body` で `$WS_TMP/pf_inbox.json` に直書き → `python _tools/apply_char.py $WS_TMP/pf_inbox.json`)。`#META` の completes_character が true なら監査(`pending_char.py --audit` → `char_audit.txt` をNG語1パスでgrep)＋`deploy_to_game.py`＋報告。false ならまた「続けて」と言う。

- **超短縮版**: 「続けて。pending_char→tsv読む→同手順で次バッチ→apply。完走なら監査＋deploy＋報告。」
- **声がぶれてきた/文脈が要約されたと感じたら** `10_人物/<キャラ>.md` を読み直す(or 新規セッションに切替)。長く続けると文脈肥大で割高になるので、**数バッチで一度フレッシュ session に切り替える**のが安い。

## ★モデル分担の関門(RUNBOOK手順2.0)
現在キャラの `10_人物/<キャラ>.md` が `status: 確定` でなければ、**校正に進まず停止し**
「<キャラ名> はペルソナ未確定。メイン(Opus)で確定が必要」と報告する。
ペルソナの深掘り・確定は**行わない**(メイン直轄)。`status: 確定` のキャラだけを継続校正する。
`status: 保留`(宇文逸/主人公)も着手しない。未確定が続いて対象が無ければ、その旨報告して終了してよい。

## 完了報告(末尾に必須)
- 見た件数 / 修正数 / 現在のキャラと進捗(pos)。
- **声の定性1行**:「保てた声の落差・なりきり」と「平坦だった/迷った箇所」を一言ずつ。痩せた回が報告で見えるようにする。
- 気になった横断項目があれば `_TODO.md` に1行(既知パターンは再掲しない)。

## 補足(RUNBOOKに無い運用情報のみ)
- 未訳(フェーズ1)は完了済み。モブ690キャラ(30行以下)は2026-06-11に一括処理済み(記録: `_phase4_proofread/_mob_done.json`)。残りは主要キャラのみ。
- `status.py` が「全キャラ完了」を表示したら、**全完了**を報告すること(手動運用なので以後の依頼は不要)。
- **コスト削減 = 機械置換の先行適用**(Sonnetは**走らせるだけ**。表は作らない):
  1. ペルソナ `10_人物/<キャラ>.md` に **`## 機械置換` 節**が**あれば**使う。
     **無ければ機械置換はスキップして通常校正へ進む**(表の作成＝ペルソナ修正は **Opus直轄**。安全な1:1置換かregister依存かの判断はSonnetでは行わない)。「表が無かった」は完了報告に1行添える。
  2. `set WS_CHAR=<キャラ>`(PowerShellは `$env:WS_CHAR="<キャラ>"`。PS5.1のCJK引数化け回避) の上で
     `python _tools/mechanical_pass.py --dry`(件数確認)→ 問題なければ `python _tools/mechanical_pass.py`(適用＋再パック)。
  3. その後 `pending_char.py` を回すと、LLMは**既に機械清掃済み**のjaを見る。残りの判断だけ直す。
  - 効果実測(司馬鈴): 369行中176行(約48%)が機械置換で自動処理。置換漏れゼロで完了監査のNG-grepも通りやすい。
  - 安全策: 本文($@$以降)だけ置換し接頭辞・タグ保持。`--dry`でいつでも無害に件数確認。**危険な置換(代名詞/コピュラ等)は内蔵ガードが自動拒否し `[警告]` を出す** → 警告が出たら**Opusへ回す**(表の修正が必要)。
