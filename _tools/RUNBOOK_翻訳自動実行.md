## フェーズ判定(毎回最初に行う)

2. 未訳が0(「未訳ユニーク残: 0」)なら**【フェーズ2:校正】**へ移る。

# 【フェーズ1】未訳の翻訳

## 役割
残っている**物語系の翻訳漏れ**(Npc・CG表・Quests任务表)を、1回につき1チャンクだけ訳して反映する。
用語統一・口調の監査役として、行き当たりばったりに訳さない。

## 手順

1. **未訳の取得**
   `python3 _tools/pending.py 40 2>&1 1>/tmp/pending.json` を実行し、`/tmp/pending.json` を読む。
   残数が0なら「全完了」を報告して終了。

2. **翻訳メモリの参照(統一のため必須)**
   既訳の辞書を読む: `_phase3_gaps/gaps_*.json` の `target_ja` が入っている行。
   Vaultの `00_ルール/口調・一人称ルール.md` と `00_ルール/基本翻訳ルール.md` も確認。
   同じ語・同じ人物が過去にどう訳されたかを必ず踏襲する。

3. **翻訳**（下記「翻訳方針」に従う）。結果を
   `{"原文中国語":"日本語訳", ...}` 形式のJSONで `/tmp/inbox.json` に書く。
   - 提示された原文すべてを埋める。判断に迷うものは仮訳でよいが、口調・用語は既訳に合わせる。
   - **トークンに余裕が無ければ無理せず件数を減らしてよい**(空 target_ja で次回再開できる)。

4. **反映＋再パック**
   `python3 _tools/apply_translations.py /tmp/inbox.json` を実行。
   gaps更新→locres書き戻し→`_work/aaWanderingSword_JP_P.pak` 再生成→`_runlog.md` 追記まで自動。

5. **報告**
   今回訳した件数、残ユニーク数(pending.pyのstderr)、気になった訳語をユーザーへ簡潔に報告。
   ※ ゲームフォルダへの差し替えはしない。チャット側で行う。

## 翻訳方針(既決の慣例)

- 原文は中国語(簡体字)、訳先は日本語。Wandering Swordの武侠世界観を保つ。
- **用語の統一**: `回合→ターン` / `气血→気血` / `真气→真気` / `持续→持続` / `恢复→回復` / `层→層`。
- **簡体字は日本語字形へ**: 効(效)・賊(贼)・竜(龙)・氷(冰)・経(经)・絶(绝)・蓮(莲)・幇(帮) など。
- **固有名詞(技・門派・人物・アイテム名)**: 漢字主体で武侠の趣を残す。揺らさない。
- **敵名・職分名**: 読みやすく(例 `五仙教弟子→五仙教の弟子`、`江湖高手→江湖の手練れ`)。
- **会話行の形式**: `ID - 話者名 $@$本文` の場合、`ID - 話者名 $@$` の部分は**そのまま残し**、
  `$@$` より後ろの本文だけを訳す。タグ `<Y>…</>` や `\r\n` `#nl` も保持する。
- **`不翻译`/`不翻譯` を含む原文は訳さない**(内部データ。pending.pyが自動除外済み)。
- 痛みや感情は直訳的にならないよう、自然な日本語の語り口で。

# 【フェーズ2】既存訳の校正(未訳が0になったら)

## 役割
既に訳されている**会話行**から「機械翻訳臭」と「キャラクターの口調のブレ」を抜く。
キュー(`_phase4_proofread/queue.json`)を Quests→CG→Npc の順に、カーソルで少しずつ前進する。

## 手順
1. `python3 _tools/pending_proofread.py 200` を実行。`/tmp/pf_batch.json` に
   `[{target,ns,key,zh(原文),ja(現訳)}]` が出る。「全完了」なら報告して終了。
1.5. **ペルソナ準備**: バッチに出てくる話者名(`ja`の `ID - 話者名 $@$`)を集め、各話者の
   `10_人物/<話者名>.md` を確認する。
   - カードが `status: 雛形` なら、先に埋める: `python3 _tools/persona_samples.py "話者名" 15` で
     セリフ例を集め、一人称・二人称・口調の癖・性格・避けたい表現を記入し `status: 仮訳` に変える。
   - `10_人物/` に無い端役は、汎用の語り口でよい(無理にカードを作らない)。
   - 併せて `00_ルール/世界観口調指針.md` を一読する。
2. 各行を監査する。話者のペルソナカードを基準に、`zh`(中国語原文)と `ja`(現在の日本語訳)を見比べ、次を直す:
   - **誤訳・意味のズレ**(原文と食い違う訳)。
   - **機械翻訳臭**: 直訳調、不自然な語順、冗長な「〜することができる」等 → 自然な日本語へ。
   - **口調のブレ**: 同一話者の一人称・語尾が過去と違う → `00_ルール/キャラ口調シート.md`(話者別の
     基準)と `00_ルール/口調・一人称ルール.md`、既訳(他の同話者行)に合わせる。話者名は
     `ID - 話者名 $@$` の部分で分かる。シートに無い話者は既訳から口調を推定し一貫させる。
   - `$@$` より前(ID・話者名)と、タグ `<Y>…</>` `\r\n` `#nl` は**変更しない**。本文だけ直す。
   - **古典の引用・漢詩・成語・故事は平準化しない**(散文化・現代語化で潰さない)。引用に気づいたら
     `00_ルール/典故・古典引用ノート.md` の「扱い方(一般原則)」に従う:出典のカノン(四書五経・諸子・
     史記等の成語・唐詩宋詞・禅語…)から**自分の知識で同定し、確立した日本語の読み下し/定訳を当てる**。
     ノートの表は代表例にすぎず、本編の引用はこれに限らない。同定できない句は漢語の形と調子を残す(触らない)。
   - **直接的な暴力・感情表現(殺す/斬る/血等)を和らげない**。
   - 問題なければ直さない(過剰な書き換えはしない)。「直しすぎ」より「触らない」を優先。
3. 修正だけを次の形式で `/tmp/pf_inbox.json` に書く:
   `{"reviewed": 200, "fixes": [{"target","ns","key","new_ja"}, ...]}`
   `reviewed` は今回提示された件数(直さなかった行も含む。カーソル前進に使う)。
4. `python3 _tools/apply_proofread.py /tmp/pf_inbox.json` を実行(反映→再パック→カーソル前進→`_prooflog.md`記録)。
5. レビュー件数・修正件数・残数・気になった点を報告。
- トークンに余裕が無ければ `reviewed` を実際に見た件数に合わせて減らしてよい(残りは次回)。
- キューは約5万行と大きい。1回の件数はトークンと相談して増減してよい(150〜250目安、軽ければさらに上げてよい)。
  ただし**1行ずつ実際に原文と訳を読んで判断**すること。件数を増やしても流し読みにしない。

## 注意
- locresの書き戻しは「文字列だけ差し替え・構造はバイト無傷」方式(検証済み)。スクリプト任せにする。
- 失敗しても `_backup/aaWanderingSword_JP_P.original.pak` から復元可能。
