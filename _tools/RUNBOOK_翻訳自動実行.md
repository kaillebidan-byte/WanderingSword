# 【フェーズ1】未訳の翻訳

> ✅ **フェーズ1は完了済み**(未訳ユニーク残0／モブ690キャラも一括処理済)。現在は常に【フェーズ2:校正】。
> 以下は手順の記録として残置(将来の差分翻訳で再利用)。`/tmp` 記述は現在 `$WS_TMP` に読み替える。

## 役割
残っている**物語系の翻訳漏れ**(Npc・CG表・Quests任务表)を、1回につき1チャンクだけ訳して反映する。
用語統一・口調の監査役として、行き当たりばったりに訳さない。

## 手順

1. **未訳の取得**
   `python3 _tools/pending.py 40 2>&1 1>/tmp/pending.json` を実行し、`/tmp/pending.json` を読む。
   残数が0なら「全完了」を報告して終了。

2. **翻訳メモリの参照(統一のため必須)**
   既訳の辞書を読む: `_phase3_gaps/gaps_*.json` の `target_ja` が入っている行。
   Vaultの `00_ルール/口調・一人称ルール.md` と `00_ルール/基本翻訳ルール.md` も確認。
   同じ語・同じ人物が過去にどう訳されたかを必ず踏襲する。

3. **翻訳**（下記「翻訳方針」に従う）。結果を
   `{"原文中国語":"日本語訳", ...}` 形式のJSONで `/tmp/inbox.json` に書く。
   - 提示された原文すべてを埋める。判断に迷うものは仮訳でよいが、口調・用語は既訳に合わせる。
   - **トークンに余裕が無ければ無理せず件数を減らしてよい**(空 target_ja で次回再開できる)。

4. **反映＋再パック**
   `python3 _tools/apply_translations.py /tmp/inbox.json` を実行。
   gaps更新→locres書き戻し→`_work/aaWanderingSword_JP_P.pak` 再生成→`_runlog.md` 追記まで自動。

5. **報告**
   今回訳した件数、残ユニーク数(pending.pyのstderr)、気になった訳語をユーザーへ簡潔に報告。
   ※ ゲームフォルダへの差し替えはしない。チャット側で行う。

## 翻訳方針(既決の慣例)

- 原文は中国語(簡体字)、訳先は日本語。Wandering Swordの武侠世界観を保つ。
- **用語の統一**: `回合→ターン` / `气血→気血` / `真气→真気` / `持续→持続` / `恢复→回復` / `层→層`。
- **簡体字は日本語字形へ**: 効(效)・賊(贼)・竜(龙)・氷(冰)・経(经)・絶(绝)・蓮(莲)・幇(帮) など。
- **固有名詞(技・門派・人物・アイテム名)**: 漢字主体で武侠の趣を残す。揺らさない。
- **敵名・職分名**: 読みやすく(例 `五仙教弟子→五仙教の弟子`、`江湖高手→江湖の手練れ`)。
- **会話行の形式**: `ID - 話者名 $@$本文` の場合、`ID - 話者名 $@$` の部分は**そのまま残し**、
  `$@$` より後ろの本文だけを訳す。タグ `<Y>…</>` や `\r\n` `#nl` も保持する。
- **`不翻译`/`不翻譯` を含む原文は訳さない**(内部データ。pending.pyが自動除外済み)。
- 痛みや感情は直訳的にならないよう、自然な日本語の語り口で。

# 【フェーズ2】既存訳の校正(未訳が0になったら)

## 役割
**キャラ単位**で既訳の会話行を校正し、「機械翻訳臭」と「口調・人称のブレ」を抜き、個性を立てる。
索引 `_phase4_proofread/by_character.json` を **脇役(主要)→宇文逸→残り** の順に処理し、
進捗は `char_progress.json`({ci, pos})で管理。1キャラずつまとめて見ることで声を揃えやすい。

## 手順
0. **【機械置換の先行適用＝コスト削減の要】** `python _tools/status.py` で現在キャラを確認。
   そのキャラが `status: 確定`(下記2.0の関門)の時のみ、ペルソナ `10_人物/<キャラ>.md` の `## 機械置換` 節
   (曖昧さゼロの1:1置換＝半端漢字・固定呼称など。register依存は入れない)を**LLMが読む前に当てる**:
   `set WS_CHAR=<キャラ>`(PSは `$env:WS_CHAR=…`)→ `python _tools/mechanical_pass.py --dry`(件数確認)→ `python _tools/mechanical_pass.py`(適用＋再パック)。
   **節が無ければ機械置換はスキップ**(表の作成＝ペルソナ修正は **Opus直轄**。安全/危険の判断はSonnetで行わない)。
   危険な置換は `mechanical_pass.py` 内蔵ガードが自動拒否し `[警告]` を出す→出たらOpusへ。未確定/保留キャラには**触らない**。詳細 [SCHEDULE_Windows_フェーズ2.md](_tools/SCHEDULE_Windows_フェーズ2.md)。
1. `python3 _tools/pending_char.py 200` を実行。**`$WS_TMP/pf_char_batch.tsv`** が出る(コスト削減のTSV: 1行目 `#META⇥{JSON meta}`=character/pos/total/completes_character、2行目 `#COLS`、以降 `target⇥ns⇥key⇥zh⇥ja` の1行1レコード。jaは機械置換後)。
1.5. **【検出器＝コスト削減・推奨】** `python _tools/detect_mistrans.py`(外部API=Gemini)。各行を**2軸**で判定しtsvを**zhオンデマンド化**: **s=意味リスク**(誤訳)＋**v=演技リスク**(原文zhが皮肉・煽り・含意・古風・敬意の含みを持ち平板訳で失われる度合い＝声に原文が要る)。**sかvが高い行だけ** `[s値/v値 理由] zh…` を残し両方低い行はzhを空に。校正は「**zh空=声色のみ調整・情報追加/脚色禁止**／**zh有=s高は誤訳直し・v高は原文の含みを声に起こす**」。役割分離: 検出器に**ペルソナを渡さない**(原文zhのトーンの有無だけ)。キー=`_tools/.secrets.json`(gitignore済)。
主=Google `gemini-2.5-flash-lite`、失敗時=**OpenRouter無料モデルへ自動フォールバック**(gemma-4-26b/qwen3-next/gpt-oss-20b/llama-3.3を順試行・429は受け流す)、両方ダメなら安全側(全zh保持)で続行。
   ※**完走時の全zh再突合監査は任意・冗長**(per-batch detectが既に全行をzh突合済＝これが正本)。やるなら `python _tools/detect_mistrans.py $WS_TMP/char_audit.json --sleep 4`(無料枠レート対策)。**常用しない**(呼び出し集中で枠枯渇)。誤訳網を厚くしたい時は校正時に `--th 0.2` でzh表示を増やす方が安全。
   stdoutは要約1行のみ＝**ファイルを読む**。`#META` から今回のキャラ名・completes を確認。中身が `#DONE` なら「全キャラ校正完了」を報告して終了。
2. **そのキャラに没入する**。読むもの(★コスト削減: **継続校正の毎回必読は persona＋世界観口調指針＋関係性・呼称マップ の3つだけ**。下記の語調技法カタログ・人称対応表・典故ノートは**都度参照**でよい):
   - `10_人物/<キャラ>.md`(ペルソナ。声の基準は「口調・癖」欄。「代表セリフ例」は校正前MT訳なので手本にしない)
   - `00_ルール/人称対応表.md`(原文自称→日本語人称。画一的な「私」にしない。register変化は許容=下記2.0)
   - `00_ルール/世界観口調指針.md` と `00_ルール/典故・古典引用ノート.md`
   - `00_ルール/語調技法カタログ_LoM参考.md`(別ゲーム高品質訳の役割語見本。一人称8種・語尾10種の実例=型録。
     **キャラの個性に合う「一人称＋語尾」の型を選ぶ参照**。LoMキャラの模倣ではなく技法だけ借りる)
   - `00_ルール/関係性・呼称マップ.md`(中大キャラ≥100行の相互呼称。**他キャラ・宇文逸への呼びかけはここを正本に**。
     A表=各キャラ→宇文逸／B表=宇文逸→相手／D=クラスタ別相互。**師兄/師弟の向きは相互一致を厳守**。端役は対象外＝汎用「少侠」等)
2.0. **【ペルソナ確定の関門 ★モデル分担の要】**
   このキャラの `10_人物/<キャラ>.md` の `status:` を確認する。**判定はモデルではなく status で行う**:
   - **`status: 確定` でない(仮訳/なし)場合 → 校正に進まず、ここで停止して報告する。**
     報告文: 「<キャラ名> はペルソナ未確定。メイン(Opus)でのペルソナ確定が必要。継続校正は確定後に。」
     スケジュール実行(継続マシン)は深掘りをせず、確定済みキャラだけを処理する。**未確定のキャラに手を入れない。**
   - **`status: 保留` の場合 → 着手せず停止して報告する。**（別途相談中の保留案件＝現状は宇文逸/主人公16,276行。
     深掘りも校正もしない。報告文: 「<キャラ名> は保留案件のため未処理。方針決定後に着手。」）
   - **`status: 確定` の場合 → 確定ペルソナをそのまま使い、手順3の継続校正へ進む。**
   理由: pos==0のペルソナ確定はMT仮訳から声を起こす最も繊細なA級判断で、上位モデル(Opus)直轄。
   確定済みへの継続校正は足場が効くため継続マシン(Sonnet)で安全(白錦pos200で実証: 確定ペルソナがあれば
   声の引き寄せ・誤訳拾いまで適切)。

2.0b. **【ペルソナ確定=メイン(Opus)直轄のときだけ実施】** 上の関門で未確定だった場合の確定手順:
   `python3 _tools/persona_derive.py "<キャラ名>"` を実行。原文ベースの自称・二人称統計＋代表セリフが出る。
   これを読んで `10_人物/<キャラ>.md` を**簡易→確定版へ書き上げる**:
   - **一人称を「相手・場面別」に明記**(例: 弟子へ=わし、道門=貧道、対外=この老いぼれ)。原文の自称変化を反映。
   - 二人称・語尾・性格・関係(誰を何と呼ぶか)も原文から具体化。`00_ルール/語調技法カタログ_LoM参考.md` で型を選ぶ。
   - 素材は**原文(zh)**。訳文やセリフ例から起こさない(MT循環を避ける)。最後に `status: 確定` へ上げる。
   分担計画は `_tools/PLAN_ペルソナ確定_Opus分割.md` を参照。
3. 各行を、`zh`(原文)と `ja`(現訳)を見比べて監査する。**原文は自由に深く参照してよい**:
   - **誤訳・意味のズレ**を正す。
   - **機械翻訳臭**(直訳調・不自然な語順・冗長な「〜することができる」等)→ 自然な日本語へ。
   - **口調・人称をそのキャラのペルソナに揃える**。一人称・語尾・癖を統一し、個性を出す。
   - **register変化は許容**: 一人称は相手・場面で訳し分けてよい(原文の自称が変われば訳も変える=個性)。
     直すのは**根拠のない揺れ(MTノイズ)だけ**。揺れに原文か関係性の根拠があるなら保持する([[人称対応表]])。
   - **古典の引用・成語・詩は平準化しない**(典故ノートのカノンから同定し定訳を当てる。不明なら触らない)。
   - **武侠語彙の訳し方に迷ったら `_tm/` の参考対訳を引く**(別ゲームLoM由来。`glossary_LegendOfMortal_zh-ja.csv`=
     武功・装備・施設等の短語、`TM_LegendOfMortal_zh-ja.csv`=文単位の言い回し)。**固有名詞は流用厳禁**(飛石幫・唐門等はWSに無い)。

   - **暴力・感情の直接表現(殺す/斬る/血等)を和らげない**。
   - `$@$` より前(ID・話者名)とタグ `<Y>…</>` `\r\n` `#nl` は**変更しない**。本文だけ。

4. 修正を `{"reviewed":200,"fixes":[{"target","ns","key","new_body"}]}` 形式で `$WS_TMP/pf_inbox.json` に**ファイル直書き**(CJKをパイプ/heredocで渡さない)。
   **`new_body` は本文($@$より後ろ)だけ**書く＝出力削減(話者ID・話者名の接頭辞は apply_char が現訳から**自動再付与**。タグ `<Y>…</>`・`\r\n`・`#nl` は本文内なので保持)。完全形 `new_ja` も後方互換で受理。`reviewed` は今回見た件数(直さない行も含む。進捗前進に使う)。
5. `python3 _tools/apply_char.py $WS_TMP/pf_inbox.json`(反映→再パック→進捗前進→`_prooflog.md`記録)。
5.5. **【最重要】1実行の進め方＝キャラの大きさで分岐(トークン節約のため)。**
   1〜5 を**200前後で数珠つなぎ**に繰り返す(各サイクル必ず `apply_char` で進捗確定。巨大な一括判断はしない)。
   各サイクルで取れる `meta.total`(現キャラの総行数)を見て、下記で分岐する。**1実行の行数予算は約600〜800行**。
   - **大物(total ≥ 約400行)＝1実行1キャラで集中。** 次のキャラには入らない。
     - 残り(total−pos)が予算以内なら完走→手順6の監査→終了。予算超なら予算ぶん進めて終了(続きは次回同キャラ)。
   - **小物(total < 約100行)＝跨ぎ連結OK。** そのキャラを完走し手順6の監査まで済ませたら、**予算が残る限り次のキャラへ続けて入る**。

     - 連結中の各キャラでも、ペルソナ確認(手順2)・完了監査(手順6)は省略しない。行数予算(約600〜800行)に達したら、その時点のキャラ完了を区切りに終了。
   - **中物(100〜399行)＝原則そのキャラを完走して終了**(次キャラへは跨がない。集中優先)。予算超なら予算ぶんで終了。
   - 目安: 1実行の総行数は約600〜800行。トークンが厳しければ減らしてよい(進捗は永続化、次回継続)。
     ※連結は「小物の立ち上げコスト(まっさらな再読)を畳む」ためのもの。大物・中物の集中は崩さない。
6. **★キャラ完了時の個性チェック**: meta の `completes_character` が true(=このバッチでそのキャラが終わる)なら、
   `python3 _tools/pending_char.py --audit "<キャラ名>"` でそのキャラの**全現訳**を一覧し、
   - 一人称・語尾・口調が**最後まで一貫しているか**を点検。ただし**register変化(相手別の自称)は正常**——
     根拠のある使い分けは潰さず、根拠のないMTノイズの揺れだけ統一する。
   - **NG語は2分類してから直す**: **(A)機械修正**=曖昧さゼロの表記揺れ(半端漢字・固定呼称)→安全に直す ／ **(B)要解釈**=呼称・一人称・口調・register→**blind一括置換せず**、場面・相手・関係で1件ずつ判断(声を殺さない)。
   - ペルソナとズレた箇所、機械的で個性の薄い箇所を拾う。
   - 直しを `{"reviewed":0,"fixes":[…]}` (reviewed=0で進捗は動かさない)で `apply_char.py` に渡す。
7. 件数・修正数・現在のキャラと進捗・気になった点を簡潔に報告。

- トークンに余裕が無ければ件数を減らしてよい(進捗は永続化され次回再開)。1回 150〜250目安、軽ければ上げてよい。

# 【フェーズ3】横串の整合(全キャラ完了後・将来)

- 用語ゆれの最終掃き出し。
