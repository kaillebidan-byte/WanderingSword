# detect 連続採点 指示（永続 Sonnet セッション用）

## 目的
`_phase4_proofread/detect_risk.json` の**未detect行（残り約5,400行＝40%）**を埋める。先頭60%は Haiku-CLI で検出済み（検証済み・本物）。残りを **Sonnet** が採点する。
**1つのセッション内で連続処理**すること（`claude -p` を毎回起動すると土台8万トークンが毎回乗って枠を溶かす——それを避けるのが永続セッションの要）。

## ★絶対禁止（最重要・前任Haikuがここで失敗した）
- **採点を「スクリプト」で自動化しない。** s/v は **あなた（Sonnet）が detect_feed.tsv の各行の zh と ja を実際に読み、内容で1行ずつ判断**して出す。
  全行に定数（例 s=0.12,v=0.3 / reason="説明"）を貼る処理は**厳禁**。それをやると検出が全部ニセになる（前回これで2,000行超を破棄した）。
- **シェルの `while` ループで全自動化しない。** コマンドは `detect_feed.py next` と `detect_feed.py apply` の2つだけ。
  **その間の採点は毎バッチ必ずあなたの応答（思考）で行う**＝ターンを重ねて回す。
- zh が空の行だけは機械的に s,v=1.0（原文なし＝検証不能で安全側）。それ以外は必ず内容judgement。

## 事前設定（セッション冒頭で1回）
- 作業ディレクトリ = プロジェクトルート。
- bash: `export WS_TMP="$PWD/_ws_tmp"; export PYTHONIOENCODING=utf-8`

## メインループ（「残り0」まで繰り返す）
1. `python _tools/detect_feed.py next 120` を実行。`残り0 (完了)` が出たら**終了**。
2. `$WS_TMP/detect_feed.tsv` を読む（各行 `i<TAB>zh<TAB>ja`、先頭 `#` は残数）。
3. 各行を下記基準で **s,v を 0〜1 採点**し、**1行1JSON（JSONL）**で `$WS_TMP/detect_feed_out.jsonl` に Write。
   `{"i":<番号>,"s":<0-1>,"v":<0-1>,"reason":"<短く。低い行は空>"}` ／ 入力の i は全て1行ずつ返す（取りこぼし厳禁）。
4. `python _tools/detect_feed.py apply $WS_TMP/detect_feed_out.jsonl` → 「残りN行」を確認。
5. 1へ戻る。

## 採点基準（★ペルソナ・キャラ設定は見ない。原文zhのトーンだけ）
- **s = 意味リスク**：意味の脱落/付加・否定や数量の反転・主体/客体/敬意の向きの取り違え・固有名詞ズレ・長文省略。明確な誤りほど高く。問題なければ 0。
- **v = 演技リスク**：原文zhが字義どおりでない含み（皮肉・反語・煽り・強い感情・古風・敬意register）を持ち平板訳で失われやすい度合い。**普通の叙述・説明・日常会話は v=0**。明確に非字義的な時だけ高く。
- recall優先：疑わしきは高め。**日本語は書き換えない・訳は作らない**（採点だけ）。

## バッチと再開
- 1バッチ 120行 目安（Sonnetなら問題ない。出力が崩れたら下げる）。
- 結果は逐次 `detect_risk.json` に保存＝**セッション切断・5h枠リセットを跨いでも `next` が残りから再開**。
- 完了確認: `python _tools/detect_feed.py next 1` で `残り0`。
