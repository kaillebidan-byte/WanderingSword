# 宇文逸 register校正 ディスパッチャ（v2.1・使い捨てワーカー方式・Sonnetセッション用）

> 使い方: **Sonnetの新規セッション**に「作業フォルダ <プロジェクト直下> で `_tools/yuwen_loop_prompt.txt` を読んで実行して」と渡すだけ。
> v1（永続1セッションで連続校正）は自己模倣ドリフトで3バッチ目から編集量が枯れる実測（17→9→1→2→1…）のため廃止（旧版は yuwen_loop_prompt.v1_persistent.bak.txt）。
> 対策＝**校正本体は毎回新規のサブエージェント（Sonnet）に1起動3バッチずつ委託**し、初回の大胆さを毎回リセットする。起動コストはコンテキストパック（yuwen_pack.md・約6千トークン）で圧縮済。

このセッション（ディスパッチャ）は**ワーカーの起動と報告受領だけ**を行う。**自分では1行も校正しない**（校正するとこのセッションにドリフトが移る）。判断仕事もしない（検査・キュー処理は別途Opus検査セッション＝`_tools/yuwen_inspect_prompt.txt`）。

■ 冒頭で1回だけ（bash・プロジェクト直下）
1. `export WS_TMP="$PWD/_ws_tmp"` ／ `export PYTHONIOENCODING=utf-8`
2. `python _tools/yuwen_pack.py` … コンテキストパック `_ws_tmp/yuwen_pack.md` を生成/更新。⚠警告（正本の見出し不一致）が出たら停止して報告。
3. `python _tools/yuwen_pending.py --plan` … 現在位置・残バッチを確認。

■ ループ（**このセッションでは4起動＝約12バッチまで**。それで停止して検査待ち）
1. **新規サブエージェント（Sonnet・汎用）を起動**。プロンプトは毎回これで固定:
   「作業フォルダ <プロジェクト直下の絶対パス> で `_tools/yuwen_worker_prompt.txt` を読み、その指示に従って最大3バッチ校正して終了せよ。」
2. ワーカーの最終報告（`WORKER完了 …` 行）を受領し、進捗1行だけ控える（バッチ範囲・cursor・変更計・flags）。
3. flagsは処理せず控えるだけ（`# OPUS要件`はreview_queueに溜まっており検査セッションが消化する）。ただし**即停止する例外**: `⚠声薄い`が2起動連続／voice系ゾーンなのに変更計が極端に少ない起動が連続——仕組みの劣化なので検査を待たず停止・報告。
4. 4起動に達したら（または #DONE／レート上限で）停止。
5. それ未満なら1へ。**必ず毎回新規ワーカー**（同一ワーカーへの継続依頼はドリフト再発＝禁止）。

■ 停止時の最終報告（最後の行・形式厳守）
- 通常（4起動完了）: `検査待ち: <n>起動<m>バッチ完了 cursor=<数>/13491 変更計<数> flags:<要約> → Opusセッションで _tools/yuwen_inspect_prompt.txt を実行してから次のディスパッチャを回す`
- 全完了: `#DONE 宇文逸 register校正 全13491本文 完了 → Opusで yuwen_inspect_prompt.txt の完了監査を実行`
- レート上限: `上限停止: batch <no>/113 cursor=<数>/13491`（cursorと記録は残る＝次セッションで同手順再開）
- 異常: `要検査停止: <理由>（cursor=<数>）`

■ 運用サイクル（人間の手順メモ）
Sonnetセッション(本ファイル・12バッチ) → 停止 → Opusセッション(`yuwen_inspect_prompt.txt`・抜き取り検査+キュー消化) → 問題なければ次のSonnetセッション … を繰り返す。deployは全完了後にOpus/別途。
