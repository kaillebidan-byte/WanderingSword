# Haiku 連続detect 指示（永続セッション用）

## 目的
`_phase4_proofread/detect_risk.json` の**未detect行（残り約5,100行）**を埋める。
**1つのセッション内で連続処理**すること。`claude -p` を毎チャンク起動すると、検出本体は小さいのに
Claude Codeのフルシステムプロンプト（約8万トークン/起動）が毎回乗り、5h枠を溶かす——これを避けるのが本方式の要。
モデルは **Haiku** を使う（採点は分類タスクなのでHaikuで十分）。

## ★絶対禁止（最重要）
- **採点を「スクリプト」で自動化しない。** s/v は **あなた（モデル）が detect_feed.tsv の各行の zh と ja を実際に読み、内容に基づいて1行ずつ判断**して出す。
  PowerShell/Python で全行に定数（例 s=0.1, v=0.15）を貼るような処理は**禁止**。それをやると検出が全部ニセになり、この作業の意味が消える。
- **シェルの `while` ループで全自動化しない。** コマンドにしてよいのは `detect_feed.py next` と `detect_feed.py apply` の2つだけ。
  その**間の採点は、毎バッチ必ずあなたの応答（思考）として行う**。＝ループは「ターンを重ねて」回す（1バッチ＝あなたが読んで→採点JSONLをWrite→apply）。
- zh が空の行だけは機械的に s,v=1.0 でよい（原文が無く検証不能＝安全側）。それ以外は必ず内容judgement。

## 事前設定（セッション冒頭で1回）
- 作業ディレクトリ = プロジェクトルート（`CLAUDE.md` のある場所）。
- bash: `export WS_TMP="$PWD/_ws_tmp"; export PYTHONIOENCODING=utf-8`
- PowerShell: `$env:WS_TMP="$PWD/_ws_tmp"; $env:PYTHONIOENCODING="utf-8"`

## メインループ（「残り0」まで繰り返す）
1. `python _tools/detect_feed.py next 120` を実行。出力に **`残り0 (完了)`** が出たら**終了**。
   （120行/ターンが目安。出力が崩れる/取りこぼすなら 80→60 に下げる。大きいほどターン数が減って安い）
2. `$WS_TMP/detect_feed.tsv` を読む。各行は `i<TAB>zh<TAB>ja`（先頭の `#` 行は残数メモ）。
3. 各行を下記基準で **s と v を 0〜1 で採点**し、**1行1JSON（JSONL）**で `$WS_TMP/detect_feed_out.jsonl` に Write する。
   形式（説明文や ``` は禁止）:
   `{"i":<番号>,"s":<0-1>,"v":<0-1>,"reason":"<短く。s,vとも低い行は空文字>"}`
   ※入力に出てきた i すべてを必ず1行ずつ返す（取りこぼし厳禁）。
4. `python _tools/detect_feed.py apply $WS_TMP/detect_feed_out.jsonl` を実行。表示される「残り未detect N行」を確認。
5. 1へ戻る。

## 採点基準（★ペルソナ・キャラ設定は見ない。原文zhのトーンの有無だけで判定）
- **s = 意味リスク**：意味の脱落/付加・否定の反転・数量や数値の違い・固有名詞のズレ・
  「誰が誰に何をするか（主体/客体/敬意の向き）」の取り違え・長文の省略。
- **v = 演技リスク**：原文zhが**字義どおりでない含み**（皮肉・反語・煽り・言外の含意・強い感情や感嘆・
  古風な言い回し・敬意/register の含み）を持ち、平板な逐語訳では**その含みが失われやすい**度合い。
  ＝校正者が声を作るのに原文を見るべき行ほど高く。
- **recall優先**：どちらも疑わしきは高めに。**日本語は書き換えない・訳は作らない**（採点だけ）。
- **zh が空の行**（原文なしで ja だけ追加された行）＝ s,v とも **1.0**（安全側＝要確認）にする。

## バッチと再開（重要）
- 1バッチ **120行** 目安（ターン数を減らすほど安い）。出力JSONLが崩れる・取りこぼすなら 80→60 に下げる。
  取りこぼした i は未detatのまま次の `next` で自動再給餌されるので、多少落としても壊れない。
- 採点結果は `detect_risk.json` に**逐次マージ保存**される。**セッションが切れても `next` が残りから再開**するので、
  別セッション・別日でも同じループを続ければよい（5h枠リセット後もそのまま継続可）。
- no_response で安全側保存されていた取りこぼし行（道玄など）も `next` が自動で再給餌する。
- 完了後の確認: `python _tools/detect_feed.py next 1` で `残り0 (完了)` を確認。
