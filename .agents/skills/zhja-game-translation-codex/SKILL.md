# 中日ゲーム翻訳 立ち上げ・品質再監査スキル

原文から高品質な日本語訳を起こし、大量処理後の人物・関係性・既訳も一次資料から再検証するための文書セット。

出典は二つ: (1) 高評価訳「活侠伝(Legend of Mortal)」JP-MODの解析、(2) 実運用プロジェクト「Wandering Sword翻訳」の知見。後者からは成功例だけでなく、典故を通常文として散文化した失敗、ペルソナの過剰信頼、静的な関係性マップ、一巡完了を品質保証と誤認した失敗、行単位校正で連続場面を壊した失敗も反映する。

## 最初に押さえる5原則

1. **翻訳の目的は声の再現**。用語統一・誤訳ゼロは前提であって目的ではない。
2. **硬い線は2本**: 原文の意味・事実・語気の方向を反転させない。原文にない情報を追加しない。
3. **資料の優先順位**: 原文・前後文・相手・時系列 > 設定正本 > ペルソナ・関係性マップ > 過去の完了記録。
4. **完了を一語で管理しない**。初回一巡、証拠収集、人物・関係監査、既訳再監査、章通読、ビルド検証、ゲーム確認を分ける。
5. **修正は場面単位、適用は決定的処理**。判断は連続会話と関係変化で行い、キー・話者接頭辞・タグ・改行・プレースホルダの保全と再パックはツールへ委ねる。

優先度は `accuracy > source_intent > consistency > efficiency > style`。用語集優先・捏造禁止。

## 実地運用からskillを改修する

このskillは固定された規則集ではなく、実地運用で検証できた知見を還元し続ける保守対象とする。

- 再現性のある誤訳、声の平坦化、過剰修正、資料の循環参照、典故誤認、構造検証漏れ、ツール事故を見つけたら、原文キー・場面・再現条件・修正結果を記録し、`SKILL.md / references / templates / tests / workflow` の適切な層へ反映する。
- 一人物・一分岐だけの癖は人物資料や監査記録へ残す。複数人物・複数場面へ一般化できる知見だけをskillへ昇格する。
- 実地で反例が出た規則へ訳文を押し込まない。一次資料を優先し、規則側を改訂する。
- skill改修と翻訳修正を同じPRで行ってよい。ただし、改修理由、一般化できる範囲、回帰検証を翻訳差分とは分けて記録する。
- 例示語尾、完成例、成功した一場面を固定テンプレートとして一括適用しない。

既訳が広範囲に荒れている既存プロジェクトでは、まず人物ペア監査で声・呼称・関係段階の局所整合を固め、その後にゲーム冒頭から章・事件単位で物語監査する二段構えを標準とする。人物ペア監査は局所整合に強く、章通読は情報順序、伏線、知識状態、感情の連続、分岐接続に強い。片方をもう片方の代替にしない。

## 着手時の二つの疑義ゲート

各バッチでは、人物資料や既訳を読む前に、原文と前後文だけで次の二つを別々に通す。**典故の疑いと、設定事実の疑いを同じ「カノン」で混同しない**。

### A. 典故・古典引用疑義ゲート

文言調、対句、四字句、詩律、経書・仏典・道家語彙、既視感のある格言が出たら、通常文として訳し始める前に `ALLUSION_REVIEW` を立てる。

1. 候補を `特定典籍の引用 / 定着した成語・故事 / 作品内の擬古文・創作書簡 / 通常の漢語文` に仮分類する。
2. 引用らしい部分の完全一致、核心句、異体字・繁簡差、前後句を検索する。
3. 出典が確認できたら、既存の日本語定訳・読み下しを優先する。
4. 出典が確認できなくても、文言調・対句・像を散文化して潰さない。
5. 四字句だから、古風だからという理由だけで典故と断定しない。誤同定も品質事故である。

記録には `候補句 / 仮分類 / 出典 / 定訳 / 根拠 / confidence` を残す。詳細は `references/05_terminology.md` §4。

### B. 設定・事実疑義ゲート

設定正本、人物資料、用語集、関係性マップ、完成例は、読む前から正しいと仮定しない。各バッチの冒頭で、原文と前後文だけから次を確認する。

1. 話者がこの時点で知っている事実は何か。
2. 台詞が示すものを、`客観事実 / 人物の認識 / 推測 / 嘘・演技 / 未解決` に分けられるか。
3. 死亡、親族、正体、動機、所属、裏切り、時系列が、資料では断定されているのに原文では言いさし・伝聞・誤認になっていないか。
4. 一つのペルソナ規則や設定説明が、異なる相手・時期・分岐を不自然に一括説明していないか。
5. 完成例、既訳、過去ログだけを根拠にした主張がないか。

一つでも該当したら `FACT_DOUBT` として扱う。

- 訳文で疑義を勝手に解消しない。原文の曖昧さ、言いさし、誤認を保持する。
- 人物の信念と作品世界の客観事実を分離する。
- 資料の主張を裏づける原文キー、場面、時系列条件を探す。
- 反証できた場合は `source-doc-fix` として資料側を改訂する。
- 裁定不能なら `unresolved` に残し、もっともらしい設定を補わない。

既存プロジェクトに旧称 `CANON_DOUBT` の台帳がある場合は履歴を壊さず残してよいが、新規記録では典故疑義と設定事実疑義を分ける。

資料参照は二つの疑義ゲートの後に行う。資料は答えを受け取る場所ではなく、一次資料から立てた仮説を照合・反証する場所とする。

## 役割分担

- **監督**: 計画、典故同定、ペルソナ作成・改訂、関係性の裁定、難所、統合、ビルド判定。
- **翻訳・監査ワーカー**: 典故らしい句へ `ALLUSION_REVIEW` を立て、確定済みの作業仮説を足場に翻訳・監査案を作る。反例を見つけたら既存資料へ押し込まず報告する。ゲームフォルダへデプロイしない。
- **決定的処理**: 計数、整形、候補抽出、キー・タグ検証、locres書き戻し、再パック、回帰走査。解釈を含めない。

サブエージェントを利用できない場合は、主担当が役割を順番に切り替える。並列化は入力範囲と出力先が重ならない独立バッチに限る。

判断の関門は成果物で制御する。ただし `status: 確定` は初回着手許可であり、最終品質保証ではない。品質段階は 04_persona、06_qa、08_pair_reaudit、09_chapter_readthrough に従って別管理する。

## 使い方

1. 02_workflow の Phase 0 からkey付きコーパスを作る。
2. Phase 1〜3 で文体基盤、話者インベントリ、用語シード、主要ペルソナを整備する。
3. Phase 4 で本文を翻訳・初回校正する。
4. 各バッチの冒頭で典故疑義ゲートを通し、引用・成語・擬古文・通常文を仮分類する。
5. 続いて設定・事実疑義ゲートを通し、原文上の事実・認識・推測・演技・未解決を分ける。
6. 一巡後は 08_pair_reaudit に従い、関係クラスタ→人物ペア→場面の順で一次資料を抽出する。
7. ペルソナ、関係性マップ、既訳を同時に検証する。敬語を扱うときは 10_register_axes に従い、呼称、敬称、文末敬体、行為敬語、上下関係を分離する。
8. 高確度の修正だけを場面単位のJSONへ分け、競合・キー・接頭辞・制御トークンを検査する。
9. locresへまとめて反映し、pakを一度だけ再生成する。
10. 主要人物ペアの高確度パス後、09_chapter_readthrough に従い、冒頭から章・事件単位で日本語通読と原文対照を分けて行う。
11. ビルド検証、章通読、ゲーム内確認を別段階で記録する。
