# 中日ゲーム翻訳 立ち上げスキル

原文(中国語)だけがある状態から、高品質な日本語訳を起こすための文書セット。
出典は二つ: (1) 高評価訳「活侠伝(Legend of Mortal)」JP-MODの解析(72,560対訳ペアの一次データで検証済み)、(2) 実運用プロジェクト「Wandering Sword翻訳」の運用知見(MT校正パイプラインから転用可能な部分のみ抽出)。

## 最初に押さえる3原則

1. **翻訳の目的は「声の再現」**。用語統一・誤訳ゼロは前提であって目的ではない。それだけに痩せると、チェックは通るのにキャラが死ぬ(実証済みの失敗パターン)。
2. **守る硬い線は2本だけ**: 原文の意味・事実・語気の方向(疑問/勧誘/推量/詠嘆/肯定否定)を反転させない。原文に無い情報の追加(脚色)をしない。この2本の内側では大胆に意訳してよい——崩すのは表現であって内容ではない。
3. **優先度**: accuracy > source_intent > consistency > efficiency > style。用語集優先・捏造禁止。

## 文書の地図(何をいつ読むか)

コスト規律: 全部を毎回読まない。フェーズごとの必読だけ読み、残りは都度参照。

## 役割分担(骨格)

- **監督**: 現在の主担当エージェント。計画・ペルソナ確定・典故同定・矛盾の裁定・抜き取り検査・デプロイ判断を担う。A級判断は委譲しない。
- **翻訳ワーカー**: 独立バッチを担当するサブエージェント。確定済みのペルソナと用語基盤に従って翻訳案を作る。未確定キャラには着手せず、デプロイもしない。
- **決定的処理**: 計数・整形・機械的変換・lintはスクリプトや適切なツールで行う。解釈を含めない。

サブエージェントを利用できない場合は、主担当エージェントが役割を順番に切り替えて同じ関門を守る。並列化は、入力範囲と出力先が重ならない独立バッチに限る。

判断の関門はエージェントの自己申告ではなく、**成果物のstatus**(ペルソナ・用語ノートの`status: 確定`)で制御する。詳細は 02_workflow と 04_persona。

## 使い方(最短経路)

1. 02_workflow の Phase 0 からゲームテキストを抽出し、key付きコーパスを作る。
2. Phase 1〜3 で文体基盤・話者インベントリ・用語シード・主要ペルソナ(監督直轄)を整備。
3. Phase 4 で `templates/worker_prompt_template.md` を実プロジェクトに合わせて具体化し、翻訳ワーカーの連続バッチで本文を訳す。
4. キャラ完了ごと・全体完了時に 06_qa の監査を通す。
