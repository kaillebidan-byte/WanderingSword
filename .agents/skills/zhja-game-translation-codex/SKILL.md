# 中日ゲーム翻訳 立ち上げ・品質再監査スキル

原文から高品質な日本語訳を起こし、大量処理後の人物・関係性・既訳も一次資料から再検証するための文書セット。

出典は二つ: (1) 高評価訳「活侠伝(Legend of Mortal)」JP-MODの解析、(2) 実運用プロジェクト「Wandering Sword翻訳」の知見。後者からは成功例だけでなく、ペルソナの過剰信頼、静的な関係性マップ、一巡完了を品質保証と誤認した失敗、行単位校正で連続場面を壊した失敗も反映する。

## 最初に押さえる5原則

1. **翻訳の目的は声の再現**。用語統一・誤訳ゼロは前提であって目的ではない。
2. **硬い線は2本**: 原文の意味・事実・語気の方向を反転させない。原文にない情報を追加しない。
3. **資料の優先順位**: 原文・前後文・相手・時系列 > 設定正本 > ペルソナ・関係性マップ > 過去の完了記録。
4. **完了を一語で管理しない**。初回一巡、証拠収集、人物・関係監査、既訳再監査、章通読、ビルド検証、ゲーム確認を分ける。
5. **修正は場面単位、適用は決定的処理**。判断は連続会話と関係変化で行い、キー・話者接頭辞・タグ・改行・プレースホルダの保全と再パックはツールへ委ねる。

優先度は `accuracy > source_intent > consistency > efficiency > style`。用語集優先・捏造禁止。

## 役割分担

- **監督**: 計画、ペルソナ作成・改訂、関係性の裁定、典故同定、難所、統合、ビルド判定。
- **翻訳・監査ワーカー**: 確定済みの作業仮説を足場に翻訳・監査案を作る。反例を見つけたら既存資料へ押し込まず報告する。ゲームフォルダへデプロイしない。
- **決定的処理**: 計数、整形、候補抽出、キー・タグ検証、locres書き戻し、再パック、回帰走査。解釈を含めない。

サブエージェントを利用できない場合は、主担当が役割を順番に切り替える。並列化は入力範囲と出力先が重ならない独立バッチに限る。

判断の関門は成果物で制御する。ただし `status: 確定` は初回着手許可であり、最終品質保証ではない。品質段階は 04_persona、06_qa、08_pair_reaudit、09_chapter_readthrough に従って別管理する。

## 使い方

1. 02_workflow の Phase 0 からkey付きコーパスを作る。
2. Phase 1〜3 で文体基盤、話者インベントリ、用語シード、主要ペルソナを整備する。
3. Phase 4 で本文を翻訳・初回校正する。
4. 一巡後は 08_pair_reaudit に従い、関係クラスタ→人物ペア→場面の順で一次資料を抽出する。
5. ペルソナ、関係性マップ、既訳を同時に検証する。敬語を扱うときは 10_register_axes に従い、呼称、敬称、文末敬体、行為敬語、上下関係を分離する。
6. 高確度の修正だけを場面単位のJSONへ分け、競合・キー・接頭辞・制御トークンを検査する。
7. locresへまとめて反映し、pakを一度だけ再生成する。
8. 主要人物ペアの高確度パス後、09_chapter_readthrough に従い、冒頭から章・事件単位で日本語通読と原文対照を分けて行う。
9. ビルド検証、章通読、ゲーム内確認を別段階で記録する。
