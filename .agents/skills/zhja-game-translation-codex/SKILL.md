# 中日ゲーム翻訳 立ち上げ・品質再監査スキル

原文(中国語)から高品質な日本語訳を起こし、大量処理後の人物・関係性・既訳も再検証するための文書セット。

出典は二つ: (1) 高評価訳「活侠伝(Legend of Mortal)」JP-MODの解析、(2) 実運用プロジェクト「Wandering Sword翻訳」の知見。後者からは成功例だけでなく、ペルソナの過剰信頼、静的な関係性マップ、一巡完了を品質保証と誤認した失敗も反映する。

## 最初に押さえる4原則

1. **翻訳の目的は声の再現**。用語統一・誤訳ゼロは前提であって目的ではない。
2. **硬い線は2本**: 原文の意味・事実・語気の方向を反転させない。原文にない情報を追加しない。
3. **資料の優先順位**: 原文・前後文・相手・時系列 > 設定正本 > ペルソナ・関係性マップ > 過去の完了記録。
4. **完了を一語で管理しない**。初回一巡、ペルソナ再検証、関係性再検証、既訳再監査、ゲーム確認を分ける。

優先度は `accuracy > source_intent > consistency > efficiency > style`。用語集優先・捏造禁止。

## 役割分担

- **監督**: 計画、ペルソナ作成・改訂、関係性の裁定、典故同定、難所、統合、デプロイ判断。
- **翻訳ワーカー**: 確定済みの作業仮説を足場に翻訳案を作る。反例を見つけたら従って潰さず報告する。デプロイしない。
- **決定的処理**: 計数、整形、機械変換、lint、キー・タグ検証。解釈を含めない。

サブエージェントを利用できない場合は、主担当が役割を順番に切り替える。並列化は入力範囲と出力先が重ならない独立バッチに限る。

判断の関門は成果物で制御する。ただし `status: 確定` は初回着手許可であり、最終品質保証ではない。品質段階は 04_persona と 06_qa に従って別管理する。

## 使い方

1. 02_workflow の Phase 0 からkey付きコーパスを作る。
2. Phase 1〜3 で文体基盤、話者インベントリ、用語シード、主要ペルソナを整備する。
3. Phase 4 で本文を翻訳・初回校正する。
4. 一巡後は関係クラスタと人物ペアで一次資料を抽出し、ペルソナ・関係性マップ・既訳を同時に再監査する。
5. 修正はキー・話者接頭辞・タグ・改行・プレースホルダを検証してから適用し、ゲーム内確認を別段階で行う。
