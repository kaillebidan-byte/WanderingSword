# ワーカー委託プロンプト雛形(ゼロ翻訳・連続バッチ用)

> 実プロジェクトの値((キャラ)・パス・バッチサイズ等)を埋めて翻訳ワーカーに渡す。
> 元になった実運用プロンプト(MT校正版)の設計思想: 冒頭で読むものを最小に絞る/優先順位を明記する/
> 出力形式を固定する/自己点検を組み込む/中断・再開に耐える/エスカレーション経路を持つ。

---

(キャラ名)((行数)行)の本文翻訳を**連続バッチで実行**する。原文(zh)から直接訳を起こす。

■ セッション冒頭で一度だけ読む(最小=コスト削減)
1. `10_人物/(キャラ名).md` … 確定ペルソナ=正本。声の核・モード表・完成例・一人称・呼称。
2. `00_ルール/世界観口調指針.md`(または references/03_style_guide.md) … 文体・定訳・直訳臭対策。
3. `00_ルール/関係性・呼称マップ.md` … B表=(キャラ)→相手。師兄/師弟の向き厳守。
4. `00_ルール/典故・古典引用ノート.md` … 古典が出た時に参照。
※ RUNBOOK全文・語調型録は読まない(都度参照)。

■ ★最優先(この仕事の目的)=声を平坦にしない
「(キャラ)がこの場面・この相手にどう喋るか」をモード表で再現する。用語統一と誤訳ゼロは前提であって目的ではない。
モード落差・比喩・相槌を平板に均さない。**一律の敬体化は最大の失敗**。

■ 連続ループ(#DONE/レート上限まで繰り返す)
1. `(バッチ取得コマンド)` → バッチファイル(`[{i, reg, partner, zh, keys}]`)+#META(batch_no/total/cursor)。#DONEなら完了報告して終了。
2. バッチを読む。#METAのregisterがこのバッチの主モード。
3. 1行ずつ zh から訳を起こす。優先順:
   - **①声・registerの再現**: モード表と完成例に声を揃える。中日の逐語は必ず固く冗長になる——語順を組み替え、冗長を削り、こなれた自然な台詞として書く。逐語に縛られない。
   - **②言語品質**: 明示代名詞を同一発話で2回以上出さない(日本語は主語を落とす)。字形は日本語標準形。「〜することができる」等の冗長を出さない。
   - **③守る線(2本だけ)**: 意味・事実・語気の方向を反転させない。原文に無い情報を足さない(脚色禁止)。
   - ④呼称は原文の呼称語(师父/道长/大哥)で判定(partnerラベルを盲信しない。直前話者≠宛先)。
   - ⑤笑い・咳は定訳表(zhを見て機能で選ぶ)。タグ・改行・プレースホルダは位置ごと完全温存。
   - ⑥古典引用らしき句は同定を試み、確信がなければ漢語の形を残して `conf:low` を立てる(散文化しない)。技名は原語維持。
   ★自己点検: (a)訳が全行同じ調子なら平坦化を疑う。(b)モード判定から逃げて無難な敬体に流れていないか。
4. 訳を `(出力ファイル)` にWriteで直書き(UTF-8。CJKをパイプ/heredocで渡さない):
   `[{"i":通番, "ja":"本文だけ", "conf":"high|mid|low", "reason":"lowの根拠を短く"}, ...]`
   ・判断不能・カノン外・ペルソナ外は reason に `# REVIEW` と明記(訳は仮で埋めてよい)。
5. `(適用コマンド)` → 反映・再パック・cursor前進・ログ記録。lowは検証キューへ自動送り。
6. 進捗1行(例「batch 12/113 M2 cursor 1320/13491」)を出して1に戻る。

■ 鉄則
- 一人称は「(一人称)」固定。register差は敬度・語尾・呼称で出す。
- (キャラ固有の鉄則をペルソナから転記: 呼称の時系列変化・心内語=常体・特殊な定訳)
- `$@$`(話者区切り)より前・タグ`<Y>…</>`・`\r\n`・`#nl`・`{0}` は不変。本文だけを訳す。
- 暴力・感情の直接表現を和らげない。
- ペルソナを拡張しない(拡張=監督直轄)。未確定キャラに当たったら停止して報告。

■ 停止時の最終1行
「#DONE (キャラ) 全(N)行 完了」/ 上限なら「上限停止: batch <no> cursor=<数>」/ 重大保留は「要監督: <理由>」。

■ 完了監査(#DONEのときだけ・1パス)
全訳文を監査ビューで一覧し、NG(一人称揺れ・呼称揺れ・典故未処理・心内語のですます)を
(A)機械修正=表記揺れ / (B)要解釈=1件ずつ に2分類して直す。再監査は1回。デプロイはしない(監督)。
