# 04 ペルソナ設計システム ── 声の作り方・検証・改訂

キャラクター翻訳の品質はペルソナ文書の質に大きく左右される。ただし、ペルソナはキャラクターそのものではなく、一次資料から作った**検証可能な作業仮説**である。作成・拡張・反例の裁定は監督直轄。ワーカーは勝手に規則を増やさないが、反例を見つけたら必ず報告する。

## 1. 着手関門と品質段階を分ける

各キャラのペルソナ文書に `status:` を持たせ、初回作業への着手可否を判定する。

- `status: 確定` → 翻訳ワーカーが本文翻訳・初回校正に着手してよい。
- `status: 仮訳` または文書なし → 着手せず停止して報告する。
- `status: 保留` → 方針相談中。触らない。

ここでの `確定` は、**十分な足場があり着手できる**という意味であって、最終的な正当性や全場面への適用を保証しない。大量処理後には別途、次の品質段階を管理する。

- `evidence_inventory`: 原文・現訳・前後文・相手・時系列を収集済み
- `persona_reviewed`: ペルソナの各規則を根拠と反例つきで再検証済み
- `relation_reviewed`: 呼称・敬度・関係変化を人物ペアで再検証済み
- `translation_reaudited`: 既訳を意味・声・関係性の三面で再監査済み
- `game_verified`: ゲーム内場面で確認済み

`status: 確定` とこれらを混同しない。

## 2. ペルソナの根拠

素材の優先順位は次の通り。

1. 原文zhと会話前後
2. 発話相手、場面、時系列、選択肢分岐
3. 同一人物・同一関係の別出現
4. 設定資料・用語正本
5. 既訳と既存ペルソナ

訳文や機械訳だけから声を起こさない。既訳を根拠にペルソナを作り、そのペルソナで既訳を正当化する循環参照を避ける。

ペルソナには最低限、次を記録する。

- **主張**: 一人称、呼称、敬度、語尾、モード切替条件
- **根拠**: 複合キー、原文の短い要約、相手、場面
- **反例**: 主張に合わない実在行と、例外か誤りかの判定
- **不明点**: 相手不明、時系列不明、原文欠落など
- **確度**: high / medium / low

根拠のない断定を増やすより、未確定として残す方が安全。

## 3. ペルソナの作り方(監督手順)

1. **話者インベントリを作る**: 全原文行から自称語・二人称・呼称マーカーを集計する。ただし集計は文脈を表さないため、結論にはしない。
2. **関係ペアを抽出する**: 主要相手ごとに、両者が同席する会話ブロックと相互呼称行を前後文つきで集める。
3. **声の核を仮置きする**: 身分・性格・発話の優先順位を、翻訳判断に直結する形で1段落にする。
4. **一人称と呼称を整理する**: 1つに固定することを目的にしない。相手・名乗り・公私・時系列で根拠ある差があるなら、最小限の複数規則として保持する。
5. **モード表を作る**: 相手カテゴリだけでなく、関係段階・場面・感情・公私を切替条件に含める。
6. **完成例を書く**: 原文から訳した手本をモード別に載せ、根拠キーを添える。完成例も反例が出れば改訂する。
7. **反例監査を行う**: 仮置きした規則に合わない原文を探し、例外・誤認・別モードを裁定する。
8. `status: 確定` に上げる。これは初回着手許可であり、再監査段階は別管理する。

### 3.1 発話可能性の関門

意味・事実・敬度が合っていても、**その人物がその状況で選ばない語彙・語順・間なら完成ではない**。ペルソナ適合だけで合格にせず、各台詞を次の観点で読み直す。

- 話者名を隠して音読し、その場面の人物として聞こえるか。すべての行へ固有口癖を足すという意味ではない。
- 同じ意味のまま別人物へ移しても、そのまま成立するほど無色になっていないか。
- 動揺、怒り、歓喜、瀕死、気まずさなど、その時の認知負荷に文長と情報順序が合っているか。感情場面を整った説明文へ均さない。
- その人物の**発話優先順位**、すなわち何を最初に言い、何を言いさし、何を言わないかが出ているか。
- 個性は呼称、語彙、間、文長、相槌、情報の出す順番で作る。キャラ付けのため原文にない事実・残虐性・感情を足さない。
- 訳文がペルソナ規則には合うのに口から出る台詞に聞こえない場合、訳文だけでなくペルソナ側を疑い、根拠と反例を再点検する。

最終確認は「誰が、誰に、なぜ今これを言うのか」。この問いに台詞の表面が答えていなければ、意味が通っていても再考する。

## 4. モード表の様式(実例: 武当育ちの主人公)

| | モード | 主な相手・条件 | 敬度・語尾 | 一人称/名乗り |
|---|---|---|---|---|
| M1 | 師門・弟子 | 師父・師伯・師叔・師兄。叱責・甘え等の場面差も記録 | 丁重を基調。親密場面では常体混入可 | 私/定型は自称「弟子」 |
| M2 | 義兄弟・仲間 | 関係成立後の盟友 | 常体・打ち解け | 私 |
| M3 | 後輩・弟分 | 妹分・師弟 | 温かく諭す常体 | 私 |
| M4 | 江湖・対外 | 他派の長・初対面・公的折衝 | 折り目正しい敬体 | 私/硬い名乗りはフルネーム |
| M5 | 親密・恋情 | 関係進展後 | 柔らかい常体・愛称 | 私 |
| M6 | 戦闘・断罪 | 敵対確定後 | 短い断定・体言止め・気迫 | 私/名乗りはフルネーム |
| M7 | 心内語 | 本文全体が括弧 | 地の常体。ですます禁止 | 多くは自称なし |

運用上の落とし穴:

- **心内語の判定は本文全体が括弧のときだけ**。(小声で)(苦笑)等は発話。
- **直前話者は話しかけ相手とは限らない**。傍白・第三者への悪態・回想が混じる。
- **呼称は関係の時系列で変わる**。弟子入り、和解、離反、正体判明の前後を一律適用しない。
- 敵対関係では相手が目上でも敬語を使わない場合がある。逆に公的折衝では敵でも敬称だけ保つ場合がある。
- 敬称、敬体、服従的な態度は別軸。まとめて一つの「敬意モード」にしない。
- 同じ相手でも、公的な名指し、親密な二人称、省略が意味分担することがある。

## 6. 語調型録(型の引き出し)

一人称の効果:
- 俺=率直・武骨 / 私=端正・理知 / 僕=線の細い若者 / あたし=蓮っ葉・姉御 / わし=老人・重鎮 / 拙者=堅物の武人 / わらわ・妾=高貴な女 / 手前=卑屈な小物。

語尾の効果:
- っす=体育会系の下っ端 / じゃ・のう=老人・仙人 / ですわ・ですの=令嬢 / だぜ・だろ=快活な兄貴分 / でございます=従者・商人 / やがる=荒くれ。

型は出発点であり、人物を型へ押し込まない。特定キャラの模倣ではなく技法だけ借りる。

三人称的自称は、日本語で省略しても態度を別の表現へ移し替えられる。自称語の表面保持より、尊大さ・謙譲・親愛の機能保持を優先する。

## 7. モード切替型ペルソナの設計

落差のあるキャラでは、固定すべきは語尾ではなく切替条件。ただし、切替条件も最初から正しいとは限らないため、人物ペアと会話ブロックで反例を探す。

設計時は次を分けて書く。

1. **発話優先順位**: 口を開く前に何を優先するか
2. **感情表出**: 感情ごとの出し方
3. **言わないこと**: 声の負の制約
4. **切替条件**: 相手、関係段階、場面、公私、感情
5. **境界例**: どちらのモードか迷う実在行
6. **反例**: 現規則に合わない実在行

境界例と反例を隠すと、ワーカーは規則を過剰適用して声を平坦化する。

## 8. 端役の扱い

行数の少ない端役は凝りすぎない。身分相応の自然な人称・口調でよい。ただし、主要人物との関係や重要事件の証言を担う端役は、行数が少なくても関係ペア監査の対象に含める。
