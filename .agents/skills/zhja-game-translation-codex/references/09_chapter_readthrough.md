# 09 章・物語順の通読再監査

## 目的

人物・関係性の再監査を一巡した後、ゲームの冒頭から章・事件・場面群の順で連続して読む。

人物ペア監査は声、呼称、関係変化の局所整合に強い。章通読は、局所監査だけでは拾いにくい次の問題を検出する。

- 情報提示の順序、伏線、回収
- 初見情報と既知情報の混同
- 同じ事件・人物・物品の呼び方の揺れ
- 直前の感情・判断とつながらない台詞
- 戦闘前後、移動後、報告場面の接続
- 分岐間の矛盾と合流後の不整合
- 行単位では自然でも、連続すると不自然な反応・語尾・テンポ
- 原文にない情報の先取り
- 既知の事実を再び初耳として扱う時系列破綻

人物ペア監査の代替ではなく、異なる方向から同じ訳を検証する後続工程とする。

## 開始条件

次を満たしてから開始する。

1. 主要関係クラスタの人物ペア高確度パスが一巡している。
2. 主要ペルソナ・関係資料に根拠、反例、確度がある。
3. 未適用の高確度修正束が残っていない。
4. 現行locres・pakが `build_verified` である。

低確度候補やゲーム内確認待ちは残っていてよい。章通読で新しい反例が出た場合、人物資料や修正済み訳も再開する。

## 監査単位

格納ファイルやkey番号ではなく、プレイヤーが経験する物語単位で区切る。

- 序章・導入
- 主要章
- 章内の事件・任務
- 戦闘前後
- 拠点帰還と報告
- 分岐と合流
- 仲間加入・離脱
- 告白、正体判明、継承、死亡などの転換点

大きすぎる場合は `章 → 事件 → 場面群` の三層に分ける。

## 二つの読み方を分ける

### 日本語通読パス

現訳だけを物語順に読む。

確認するもの:

- 日本語としての流れ
- 会話の受け答え
- 感情の連続
- 説明の重複・不足
- テンポ
- 章の開始時と終了時の理解

原文を横に置かず、プレイヤーの読書体験を先に確認する。

### 原文対照パス

次に原文と現訳を場面単位で突き合わせる。

確認するもの:

- 意味、主客、否定、条件、推量、命令
- 情報の追加・脱落・先取り
- 固有名詞、事件名、物品名、技、門派
- 知識状態と時系列
- 声、敬度、呼称、関係段階

最初から一行ずつ対照すると、章全体の読後感や情報順序を見失いやすいため、二つのパスを混ぜない。

## 章開始時の情報状態

各章・事件について次を記録する。

- プレイヤーが知っている人物関係
- 判明済みの正体・目的・事件
- 未回収の伏線
- 主人公と仲間が知っている情報
- 敵や第三者だけが知っている情報
- 章内で初めて判明する情報

訳文がこの情報境界を越えて先取りしていないか確認する。

## 判定軸

### 意味

- 誰が誰に何をしたか
- 否定、推量、疑問、命令、許可
- 因果、条件、時系列
- 情報の追加・脱落

### 声

- 直前発話への反応
- 感情の上昇・沈静
- 短句、沈黙、言いさし、効果音
- 章内の人物モード変化

### 関係

- 呼称、二人称、敬体・常体
- 公私、敵味方、上下関係
- 関係成立、悪化、和解、離反の前後

### 物語

- 伏線と回収
- 初見情報と既知情報
- 章の目的と結果
- 分岐間の整合
- 次章への接続

## 裁定

各候補を次へ分ける。

- `fix`: 原文・場面・物語順から修正根拠がある。
- `keep`: 一見不統一でも、時系列・分岐・情報差の根拠がある。
- `source-doc-fix`: ペルソナ、用語、関係資料、章台帳側が誤っている。
- `unresolved`: 分岐順・演出・話者・ゲーム内状態が不足している。

好みだけの言い換えは `fix` にしない。

## 一章ごとの成果物

- 章・事件の範囲とkey座標
- 場面順
- 登場人物と関係段階
- 章開始時の情報状態
- 章終了時に判明した情報
- 重要語・事件名・物品名
- `fix / keep / source-doc-fix / unresolved`
- 高確度修正JSON
- 意図的保持一覧
- 次章へ持ち越す未解決事項
- 適用・ビルド検証記録

## 完了段階

- `chapter_inventory`: 範囲、場面順、人物、情報状態を棚卸し済み。
- `chapter_reaudited`: 日本語通読と原文対照の両方を完了。
- `chapter_build_verified`: 修正をlocresへ反映し、pakと回帰検証を完了。
- `chapter_game_verified`: ゲーム内で重要場面、分岐、表示を確認。

全章の `chapter_reaudited` が完了しても、ゲーム内で演出・表示・分岐を確認していない限り、プロジェクト全体を `game_verified` としない。
