# 06 品質管理 ── 検証・監査・反面教師

## 1. ワーカーの自己点検(バッチ中)

- (a) 自分の修正・訳の工夫が「呼称・一人称・笑い」ばかりなら、**声を見落としている**——非平坦化の目で読み直す。
- (b) register(敬体/常体)だけを見て、代名詞反復・字形・意味ズレを素通りしていないか。変更・推敲が極端に少ないバッチほど疑わしい。
- (c) 既定registerが無い混在バッチは判定から逃げやすい。相手と本文からモードを能動的に判定し、判定できても最小限(呼称だけ)で済ませない。
- 迷ったら `conf:low` + 理由。判断不能は `# REVIEW` を明記。**旗を立てるのは失敗ではない。無言の誤魔化しが失敗**。

## 2. キャラ完了時の監査(1キャラ=1パス)

1. そのキャラの全訳文を一覧出力する(監査ビュー)。
2. 点検項目: 一人称・語尾・口調の一貫性 / 呼称のB表整合 / 典故の処理 / 心内語の常体 / タグ破損。
   - **register変化(相手別の使い分け)は正常**。潰すのは根拠のない揺れだけ。揺れには「原文の自称の違い」か「関係」の根拠が要る。
3. **NG検出は2分類してから直す**:
   - (A)機械修正=曖昧さゼロの表記揺れ(半端漢字・固定呼称)→安全に一括修正。
   - (B)要解釈=呼称・一人称・register→**一括置換禁止**。場面・相手で1件ずつ(声を殺さない)。
4. 再監査は1回まで(無限ループ禁止)。

## 3. 横串整合(全体完了時)

- 共通人物の呼称: 全員が主人公を何と呼ぶか、門派の上下が話者をまたいで一貫しているか。
- 固有名詞・事件名の統一。用語ゆれの最終掃き出し。
- lintスクリプト化推奨: 簡体字残り/タグ破損(名前付き閉じタグ)/明示代名詞の同一発話内反復/現代語NGリスト(マジ・ヤバい・エリート等)/です・ます混入(心内語・地の文)。

## 4. 監督の抜き取り検査

- 10バッチごとに数十行を原文と突き合わせる。傾向不良(平坦化・呼称ズレ・訳し過ぎ)が出たら**個別修正ではなくワーカープロンプトを改訂**して再開。
- `conf:low` キューを裁定し、判断根拠をペルソナ・用語ノートに還元する(同じ迷いを二度させない)。
- ワーカーの報告に引用された対訳は**一次データで実在検証**する。解析・報告系のタスクでは捏造引用が実際に発生する(実測: 33組中1組が捏造)。

## 5. 実装検証

- ゲーム内表示: フォント・文字化け・改行位置・UIはみ出し・タグ描画。
- 表示欄の字数超過は「漢字1字流用」への切り替えで対処(03§7)。
- デプロイは監督判断。ワーカーはしない。バックアップから復元可能な状態を常に保つ。

## 6. 反面教師カタログ(高評価訳にも実在した欠陥——同じ穴に落ちない)

量産過程で高品質訳でも起こった実例。納品前チェックリストの根拠:

1. **原文文字の混入**: 「あなた**的**大師兄は…」(中国語助詞「的」の残留)。→ lintで検出可能。
2. **誤変換**: 「顔に泥を**濡れよう**か」(塗る→濡れる)。→ 用語一貫チェックで検出可能。
3. **メモの本番残留**: 訳文冒頭に「小梅=大師兄」というデバッグ用話者メモが残存。→ 「=」等のメタ文字パターンをlint。
4. **助詞・表記の微ゆれ**: 同一原文が「上官家令嬢/上官家の令嬢」で分裂。→ 同一key系列の突合。
5. **設定と食い違う訳**: 「大金皇帝」→「大宋皇帝」(単発の国号誤り。他所では正しい)。→ 固有名詞の全出現を突合。
6. **抽象度の放棄**: 「玩家社群」→「Discord」(一般名詞を固有サービス名へ)。意図的な実装差し替えなら記録を残す。訳として扱わない。

## 7. 納品前チェックリスト(最終)

- [ ] 地の文に「です・ます」が混入していない。心内語(全文括弧)が常体。
- [ ] 主要キャラの一人称・語尾が全出現で一貫(根拠あるregister変化を除く)。
- [ ] 師兄/師弟の向きが相互一致。
- [ ] 簡体字・中国語異体字・原文助詞の残留ゼロ。
- [ ] タグ・改行・プレースホルダが原文と同数・同位置。閉じタグ形式が正しい。
- [ ] 状態異常名・技名・固有名詞の全出現が用語ノートと一致。
- [ ] 罵倒・暴力表現が婉曲化されていない。
- [ ] 典故が散文化されていない。技名が読み下されていない。
- [ ] `conf:low` キューがすべて裁定済み。
